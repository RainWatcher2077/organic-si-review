# 底账、报告与交付验证

## 统一记录

| 记录 | 必填内容 |
| --- | --- |
| 来源 | 来源 ID、相对或完整路径、版次、用途、初始及最终 SHA-256、页数（适用时）、纳入或排除及原因。旧报告和脚本输出标为派生证据。 |
| 问题 | 稳定 ID、专题、对象、标题、影响、证据状态、观测/比较、依据及作者动作、证据锚点、复核人/方式。建议说明是否需作者确认。 |
| 证据锚点 | 来源 ID、PDF 物理页（从 1 起）、印刷页（可读时）、对象、图版/节名/短文本。可以附高亮区域或计算行。非 PDF 使用真实章节、文件、行或记录 ID。比较涉及几个位置就列几个。 |
| 覆盖 | 以检查队列为分母，按检查单元记实查内容和方式。标明原页目检、原始数据复算、文本/提取、OCR、抽查，以及缺失、无法读取、排除或未做。附可回溯的页或对象列表。抽查只将实际检查的单元计入完成，纯文本读到图注不计为已看图。 |
| 上轮状态 | 每个旧 ID 恰有一个状态，附新版锚点或缺失/排除原因，及关联本轮问题 ID（可多对多）。状态为已修复、部分修复、仍存在、无法核实、本轮排除。新版删去文字时检查相同主张是否在别处保留，避免把移位视为修复。 |

影响按对结构身份、核心结论、可复现性及投稿理解的实际后果分高、中、低。证据状态用确定（来源直接支持）、待核（证据不足或仍有解释）、建议（表述或格式改进）。例如 SI 与图的标号确实冲突可列为确定，作者实际用的样品仍可待核。发现未发表信息不作为外部检索词，也不写入需要联网的交互组件。

## 报告与 PDF 批注副本

报告先给优先处理事项，再给范围、未覆盖、分工及实际完成的复核、完整条目和上轮状态。每条提供锚点，图文冲突需双方可达。以 JSON 底账为正式 ID 来源。需要表格处理时同时提供 CSV。确定问题和待核问题分开筛选。避免在可分享的输出里保留临时路径、无关个人信息或大量工作日志。

需要批注时由主审从原件单独另存。文本用高亮，结构、箭头或无文字层的图用框/批注。附稳定 ID 和简短核对动作。只有无法精确圈定时才用页级批注，并在底账说明。页链接以相对路径加物理页为宜，例如 `批注副本.pdf#page=4`，且提供可人工定位的标签。报告独立导出为 PDF 时检查长表、上下标、断页、中文和页码可读性。

## 本地 HTML 清单

全面审阅的 HTML 默认支持搜索、按专题/影响/证据状态筛选，并提供逐条「已修改」。报告与底账版本或 ID 命名空间绑定，勾选、取消与刷新恢复都按稳定 ID 处理。**「已修改」是作者个人勾选，「已修复」由本轮证据判定。** 两类状态独立呈现。用本地存储作便利功能，提供「保存进度副本」导出含当前勾选状态的独立 HTML，重新打开后可继续用，保留相对 PDF 链接。本地存储不可用时明确提示且可导出。不得通过默认筛选隐藏未解决项。网页本地可打开，不加载远程脚本、字体或追踪资源。只需定点结果时无需搭建网页。

## 交付前核验

1. 核对开始与结束的来源哈希。若审阅中输入变了，标明受影响的版本和证据，先重新确认目标并重跑受影响检查，再报告其覆盖。不能把先前版次的证据记到当前版。
2. 比对报告、结构化底账、旧项状态和批注 ID。检查问题 ID 唯一，证据页在正确文件及页码范围内，旧 ID 无缺失。对照输入清单及分工回传核覆盖分母和排除项。
3. 检查批注副本页数、页序和纸面内容。适用工具可用时，在隐藏批注情况下比较原件与副本的渲染，再打开批注验证关键锚点。记录是全量比对、抽样还是只核页数。签名、表单、书签等存在时检查副本是否需要保留，并记录限制。
4. 在实际可用的浏览器打开 HTML，核搜索和筛选组合、勾选和取消、刷新、另存后重开、相对链接及窄屏。验证取消操作不会被更旧的浏览器状态或嵌入状态恢复。在本地存储不可用时也验证导出。无法运行浏览器时标注测试边界，不能仅凭阅读代码声称已交互验证。
5. 交付列出审阅版本、报告和副本、最优先问题、待作者确认的数据与未覆盖的项，说明检查了哪些实际功能。若完成中有裁决改变或独立复核缺失，简述其影响。
